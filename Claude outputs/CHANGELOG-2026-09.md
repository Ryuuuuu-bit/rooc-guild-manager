## 1. บั๊ก: bot restart ข้ามการ reset เที่ยงคืน
**Commit:** `5c26675` — deploy แล้ว (bot) ✅

**ปัญหา:** `bot/index.ts` ตั้งค่าตัวแปร `lastResetThaiDate` เป็น "วันนี้" ทุกครั้งที่ bot เริ่มทำงานใหม่ (เช่นตอน Railway redeploy กลางวัน) ทำให้ bot คิดว่า reset ของวันนั้น "ทำไปแล้ว" ทั้งที่ยังไม่เคยรัน ส่งผลให้การ reset สถานะ busy/ลา ประจำวัน และการแจ้งลาล่วงหน้าที่ถึงกำหนด ถูกข้ามไปจนกว่าจะถึงเที่ยงคืนถัดไป (log จะโชว์ "Leave cancelled/returned" ล่าช้ากว่าที่ควรจะเป็น)

**แก้:** เปลี่ยนค่าเริ่มต้นเป็น `null` แล้วรัน `runMidnightResetCheck()` ทันทีตอน bot เริ่มทำงาน (ปลอดภัยเพราะ `resetDailyBusyLists()` เป็น idempotent — รันซ้ำได้ไม่เสียหาย)

## 2. Transaction safety — กันข้อมูลค้างครึ่งเดียวตอน redeploy
**Commit:** `101afe9` — deploy แล้ว (bot) ✅

**ปัญหา:** พบว่า `bot/reactions.ts`, `bot/leave-schedule.ts`, `bot/midnight-reset.ts` มีจุดที่ update ฐานข้อมูลหลายคำสั่งแยกกัน (ลบแล้วค่อย insert) โดยไม่ได้ครอบด้วย transaction — ถ้า Railway redeploy ตัดตอนกลางคัน (ซึ่งเกิดขึ้นจริงเป็นประจำ) อาจทำให้ข้อมูลค้างอยู่ครึ่งเดียว เช่น ลบสถานะ busy ไปแล้วแต่ยังไม่ insert สถานะใหม่ ทำให้สมาชิกถูกจัดสถานะผิดถาวร

**แก้:** ครอบทุกจุดที่เกี่ยวข้องด้วย `db.transaction()` (แต่ยังคง Discord API call เช่น DM ไว้นอก transaction เสมอ)

## 6. หน้า Party — เตือนใครลาล่วงหน้าไว้ก่อนจัดปาร์ตี้
**Commit:** `ee99274` — deploy แล้ว (web) ✅

เพิ่มแถบเตือนสีเหลืองอำพัน (⚠ Upcoming leave on file) ใต้แถบสรุปของบอร์ดในหน้า /party — โชว์ชื่อ + วันที่ ของสมาชิกที่แจ้งลาล่วงหน้าไว้ (ผ่าน /leave) สำหรับบอร์ดนั้น ตั้งแต่วันนี้เป็นต้นไป เพราะบอร์ดปาร์ตี้เองไม่มีมิติเรื่องวันที่ (ไม่รู้ว่า "วันนี้" คือวันไหนของสัปดาห์) เลยมองไม่เห็นคนที่ลาไว้ล่วงหน้าสำหรับกิจกรรมที่ยังไม่ถึง — ตอนนี้เปิดหน้า /party ก่อนกิจกรรม 1 วันจะเห็นชื่อคนที่ลาไว้แล้วทันที ไม่ต้องไปเช็คหน้า Calendar แยก

## 7. หน้า Party — รีวิวปุ่มทั้งหมด แก้ error-handling
**Commit:** `7497e83` — deploy แล้ว (web) ✅

รีวิวปุ่มทุกปุ่มในหน้า /party ตามคำขอ พบว่าปุ่มต่อไปนี้ไม่มีการดักจับ error ที่เกิดจาก server action "throw" จริง ๆ (ไม่ใช่แค่ return ว่า fail) เช่น DB สะดุดตอน redeploy — ถ้าเกิดเหตุการณ์แบบนี้ ปุ่มจะดูเหมือนไม่มีอะไรเกิดขึ้นเลย ไม่มี error โชว์ เสี่ยงกดซ้ำ:
- Rename Board, Delete Board, Clear This Board
- New Group, Rename Group, Delete Group, New Party, Delete Party
- หน้าต่าง Post Leave in Discord, Announce as Image, Load Template (ค้างที่ "Loading..."/"Posting..." ตลอดไปถ้า fetch พลาด)

**แก้:** ใส่ try/catch/finally ให้ครบทุกจุด ถ้า fail จะมี alert แจ้งชัดเจนแทนที่จะเงียบ

## 8. Loot Auction Queue — เอาปุ่ม auto-post ออก เพิ่มปุ่ม Copy
**Commit:** `7497e83` — deploy แล้ว (web) ✅

**ปัญหา:** ปุ่ม "Post to Discord" เปิด modal ที่โหลดรายชื่อ channel โดยไม่มี error handling — ถ้า fetch พลาด modal จะค้างที่ "Loading..." ตลอดไป ไม่มี error โชว์เลย ตรงกับอาการ "กดแล้วไม่ขึ้น" ที่แจ้งมา

**แก้ตามที่ขอ:**
- เอาปุ่ม "Post to Discord" และ modal ออกทั้งหมด เหลือแค่ปุ่ม **"Copy Message"** (คัดลอกข้อความไปวางเอง)
- เพิ่มปุ่ม **"Copy"** ในแต่ละแถวของ Recent History — แต่ตั้งใจให้คัดลอก **แค่รายชื่อเฉย ๆ ไม่ใส่เลขลำดับ** เพราะเลขลำดับของรอบเก่า ๆ ไม่ได้ถูกเก็บไว้ในระบบ (คำนวณสดตอนรันรอบใหม่เท่านั้น) ถ้าพยายามคำนวณย้อนหลังเสี่ยงได้เลขผิดไปใส่ในประกาศประมูล
